# 대기실 UI 재구성 (2026-10-04, v3 갱신 2026-10-05)

## v3 (2026-10-05) — 목업과 실제 화면이 달랐던 이유와 수정

**증상**: `Docs/preview/lobby_mock.html`과 실제 대기실 화면이 다르게 나왔다.

**원인 3가지**
1. v2 `.ui`는 템플릿(style-1-black) 프레임 스프라이트(패널 `785cacd8…`, 카드 `d9d1070e…` 아이템 슬롯 등)를 썼다. 이 아트의 실제 모양을 확인할 수 없어서 목업은 CSS(그라데이션·테두리·흐린 그림자)로 비슷하게 흉내 냈다. 실제 아트는 그 흉내와 달랐고, 특히 작은 아이템 슬롯 프레임을 340×210 카드로 늘리면 모양이 크게 달라진다.
2. 선택 글로우를 스크립트가 진영색 **불투명 100%**로 칠했다(`SetCardSelected`). 목업에선 은은한 빛이었지만 게임에선 카드 둘레의 두꺼운 색 띠로 보였다.
3. 목업은 원형 배지, 흐린 그림자 같은 엔진에 없는 효과를 썼다.

**수정**
- `.ui`를 **엔진 기본 스프라이트(둥근 사각) 색 겹침만으로** 다시 만들었다(v3, 엔티티 114개). 판은 바깥 판(테두리색)과 3px 안쪽 `Fill`(면색) 두 겹이다. 글로우는 카드보다 24px 큰 반투명 판(28%) 한 장이다. 템플릿 아트는 쓰지 않는다.
- 카드 선택 표시: 테두리(카드 버튼 스프라이트)가 진영색으로 바뀌고, 글로우를 반투명으로 켜고, "선택됨" 칩을 보인다.
- 목업 렌더러도 `.ui` 값을 그대로 그리도록 바꿨다(둥근 사각 × Color, displayOrder 순서, CSS 효과 없음). 이제 목업과 게임은 같은 원리로 그려진다. 다른 점은 글꼴(게임은 Maple)과 본진 아이콘(목업은 자리 표시)뿐이다.
- 목업 하단 버튼으로 4가지 상태(처음 / 진영만 / 직업까지 / 준비 완료)를 바꿔 볼 수 있다. 캡처: `Docs/preview/lobby_mock.png`.

**준비 완료 버튼 (신규)**
- 위치: 선택 패널 하단 오른쪽(`SelectPanel/ReadyBtn`, 340×62). 요약 칸은 왼쪽 720으로 줄였다.
- 3상태: 회색 "직업을 고르세요"(진영·직업 미선택) → 금색 "준비 완료" → 초록 "준비 취소"(준비됨). 선택 전에 누르면 토스트 "진영과 직업을 먼저 고르세요".
- 서버: `PlayerInfo.IsReady`(@Sync 신규). `RequestSetReady`가 진영·직업을 다 골랐을 때만 준비를 허락한다. 진영이나 직업을 바꾸면 서버가 준비를 자동으로 푼다. 로비 복귀 시 초기화한다.
- 게임 시작 조건: "전원이 진영·직업 선택"에서 **"전원이 준비 완료"**로 바꿨다. 안내 문구도 "모든 플레이어가 준비 완료를 누르면 N초 후 게임이 시작됩니다"로 바꿨다.
- 참가자 행 상태 칩: 선택 중(회색) / 선택 완료(남색) / 준비 완료(금색).

**바뀐 파일**: `ui/LobbyGroup.ui`(루트 UUID `90c9622e…` 유지, 바인딩 20개 재주입, `btnReady` 추가), `LobbyController.mlua`, `PlayerInfo.mlua`, `Docs/preview/lobby_mock.html`·`lobby_mock.png`.
**확인할 것**: 기본 스프라이트의 모서리 반경이 목업(8px)과 다르면 얇은 띠(강조띠 6px, 세로줄 6px)의 끝 모양만 조금 달라진다. 레이아웃·색은 같다.

## 무엇이 바뀌었나

대기실 화면을 "진영 → 직업" 2단계 선택 + "참가자 현황" 패널로 다시 짰다.

```
┌──────────────────────── CAMP WAR 대기실 ────────────────────────┐
│ ┌─ 1. 진영 선택 ───────────────────────┐  ┌─ 참가자 N / 4 ───┐ │
│ │ [세계수 아이콘] [신수 아이콘] [넥서스]  │  │ 이름 (나)   [진영] │ │
│ │  모험가        시그너스     에델슈타인 │  │ 직업/상태 [준비완료]│ │
│ │ ─ 2. 직업 선택 — 모험가 ─────────────  │  │ … 4줄 …           │ │
│ │ [직업1][직업2][직업3][직업4][직업5]      │  │                   │ │
│ │ 내 선택: 모험가 / 다크나이트           │  │                   │ │
│ └──────────────────────────────────────┘  └───────────────────┘ │
│              대기 2명 / 준비 1명  ·  N초 후 게임을 시작합니다      │
└─────────────────────────────────────────────────────────────────┘
```

- 진영 카드 3장: 본진 스프라이트(세계수/신수/넥서스) + 이름 + 한 줄 설명. 고른 카드만 진영색(초록/파랑/주황).
- 직업 카드 5장: 진영을 고르기 전엔 숨기고 안내 문구만 보여 준다. 고른 직업만 진영색.
- 참가자 패널: 최대 4줄. 내 행이 맨 위, 나머지는 닉네임순. 각 행에 **이름 / 진영 칩 / 직업(또는 "고르는 중") / 준비 상태 칩**. 빈 자리는 "빈 자리 / 입장 대기 중".
- 하단: 기존 `대기 N명 / 준비 N명`과 카운트다운 문구 그대로.

## 동작 방식

- 다른 플레이어의 선택은 **서버 RPC 없이** 읽는다. `PlayerInfo.SelectedCamp` / `SelectedHeroId`가 `@Sync`라 모든 클라이언트가 값을 받으므로, `LobbyController`가 클라에서 0.5초마다 `_UserService:GetUsersByMapName("map01")`을 돌며 패널을 다시 그린다(`RefreshRoster`).
- 선택 요청/검증 흐름(`RequestSelectCamp` / `RequestSelectHero`, 진영 계열 밖 직업 거부, 진영 변경 시 직업 초기화)은 그대로다.
- 카운트다운 Multicast는 **초가 바뀔 때만** 보내도록 고쳤다(기존엔 매 프레임 전송 — 리뷰 문서 4절 1-1).
- **v2 비주얼**: 패널·카드·제목 바는 `msw-ui-system` 템플릿 style-1-black의 9-slice 프레임 RUID(`785cacd8…` 패널, `d9d1070e…` 슬롯 프레임, `ab150cd6…` 패턴 바, `c2c6e3d0…` 타이틀 바, `129f0248…` 내부 패널, `b94f57f5…` 보조 패널)를 쓴다. 카드마다 진영색 강조띠(`Accent`), 선택 시 켜지는 카드 뒤 글로우(형제 `<카드>_Glow`)와 "선택됨" 칩(`Check`), 참가자 행 왼쪽 진영색 세로줄(`Stripe`), 배경 별안개 파티클(`Stars`, UIAreaParticle StarFog)이 있다. 글자는 Maple 폰트 + Underlay 그림자, 제목/이름은 외곽선.
- 선택 표시는 스크립트가 `Glow`/`Check`의 Enable과 `Accent` 색으로 그린다(`SetCardSelected`). 버튼 8개는 `ButtonComponent.Transition = None`. ColorTint를 켜 두면 hover/press 때 엔진이 카드 색을 덮어쓴다.
- 미리보기: `Docs/preview/lobby_mock.html`(.ui 좌표·크기를 그대로 그린 HTML 목업, 템플릿 아트는 CSS로 흉내).

## 팀원이 할 일

1. 두 파일을 Maker 프로젝트에 넣고 **Refresh**.
2. 플레이 → 로비에서 진영 카드 클릭 → 직업 카드 5장 표시 → 직업 클릭 → 요약/참가자 행 갱신 확인.
3. 2인 접속으로 상대 행에 상대 진영·직업·"준비 완료"가 뜨는지, 상대가 진영을 바꾸면 직업이 "고르는 중"으로 돌아가는지 확인.
4. 본진 스프라이트가 카드 안 116×116에서 너무 작거나 잘리면 `SelectPanel/Camp_*/Icon`의 `rect_size`만 조정(빌더 `patch`).
5. 템플릿 프레임 아트가 이 Mac에선 보이지 않아 실제 색감은 확인 못 했다. 프레임이 너무 밝거나 어두우면 `SelectPanel`/`PlayersPanel`/`Camp_*`/`Job*`의 `SpriteGUIRenderer.Color`를 회색 톤으로 조정하면 된다.

## 알고 있는 한계

- 직업 카드에 초상화가 없다(이름만). 직업별 초상 RUID가 정해지면 `Job1~5` 버튼에 자식 `Icon` 스프라이트를 추가하고 `ShowJobPanel`에서 RUID를 바꿔 끼우면 된다.
- 참가자 패널은 4줄 고정(`MaxPlayers`). 인원을 늘리면 행 추가 + `row5…` 바인딩이 필요하다.
- `MinPlayers = 1`과 게임 시작 후 재시작 가드 없음은 이번 범위 밖(리뷰 문서 0-7 참고).
- 모바일 폰트 24 미만 경고가 칩/부제목에 있지만 이 게임은 PC 전용 조작이라 그대로 뒀다.
