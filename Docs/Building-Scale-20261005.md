# 건물 크기 비율 정리 (2026-10-05)

## 문제
건물 모델 35개의 `TransformComponent.Scale`이 전부 1.2(본진 세계수·신수만 0.6)로 같았다. 그런데 건물 스프라이트는 팀이 직접 올린 것이라 원본 픽셀 크기가 제각각이어서, 화면에 보이는 크기가 역할과 상관없이 뒤죽박죽이었다. 공개 리소스 API로는 팀 업로드 스프라이트(404)의 크기를 알 수 없고, `메커톤/건물/` 원본 PNG는 대부분 배경이 붙은 1254px 원화라 업로드본과 크기가 다르다.

## 방식: 실행 중 스프라이트를 읽어 자동 배율
- `Structure_Info.TargetSize`(월드 유닛) = 화면에 보이는 크기(스프라이트 가로×세로의 **기하평균**). 0이면 기존처럼 모델 Scale을 그대로 쓴다.
- 서버가 건물 생성 시(`Structure_Info.OnBeginPlay`) 스프라이트를 읽어 `Scale = TargetSize / √(w·h)`로 정한다. 아주 길쭉한 스프라이트는 긴 변이 TargetSize×1.35를 넘지 않게 줄인다. 좌우 반전(음수 x)은 유지한다.
- 서버가 스프라이트를 못 읽으면 1초 뒤 소유자 클라가 측정값을 서버로 보내 대신 확정한다(`ReportSpriteBounds`).
- 확정되면 `AutoSized`(Sync)가 켜지고, 클라는 체력바 기준값을 다시 읽는다.

## 크기 등급 (스타2 점유 칸 파일런 2 : 게이트 3 : 넥서스 5 비율)
| 등급 | TargetSize | 해당 건물 |
|---|---|---|
| 본진 (넥서스) | 3.6 | 세계수, 신수, 레지스탕스 본부 |
| 지역 거점 / 최종 테크 | 2.6 | 모험가 전초지 4종 / 시그너스 신전, 레지스탕스 사령부 |
| 생산 (게이트웨이) | 2.4 | 사냥터·채석장·요정의 숲·지하철 / 병영·골렘의 사원·정령의 제단 / 안드로이드 공장·폐광 무기고·비행선 격납고 |
| 테크 (사이버네틱스 코어) | 2.2 | 버섯의 성, 엘리니아 마나 제단 / 여제의 알현실 / 레지스탕스 연구소 |
| 업그레이드 (포지) | 2.1 | 무기점·전사의 성소·마법 도서관·다크로드의 은신처 / 훈련소·사령부·정령의 성소 / 정비소·발전소 |
| 인구·영역 (파일런) | 1.5 | 스포아 군락, 신수의 가호, 임시 거주구 |

참고 유닛 크기: 일반 유닛 0.4~1.0, 골렘·게오르크 2.3~2.6. 본진은 일반 유닛 약 5~6마리 폭이다.
값을 바꾸고 싶으면 Maker 인스펙터에서 각 건물 모델의 Structure_Info "목표 크기"를 고치거나, `메이플RTS_tools/scale/apply_building_sizes.cjs`의 TIER 표를 고쳐 다시 실행한다.

## 함께 맞춘 것
| 항목 | 내용 |
|---|---|
| 충돌 박스 | 템플릿 기본값(1.63×1.98)을 그대로 두던 24개는 `AutoFitCollider=true` — 스프라이트 폭 80%, 아래쪽 70% 높이로 자동 설정. 팀원이 손으로 맞춘 11개(모험가 전초지 4·생산 3·테크 2, 세계수, 스포아 군락 — 원/다각형 포함)는 박스 값을 유지하고 배율만 따라간다 |
| 체력바·선택 테두리 | 새 박스 기준으로 다시 배치. 두께는 월드 기준 고정(배경 0.33, 채움 0.24, 박스 위 여백 0.4)이라 건물 크기와 무관하게 같은 굵기 |
| 건설 고스트 | 같은 계산으로 고스트 배율·겹침 검사 박스(크기+피벗 기준 오프셋)를 완공 후 건물과 일치시킴. 고스트가 데이터셋 Ruid로 다른 그림을 그리면 그 그림 기준으로 같은 목표 크기에 맞춤 |
| 본진 스폰 | 일꾼·영웅을 본진 박스 아래에 놓기 전에 자동 크기를 먼저 확정 |

## 확인할 로그
- 서버: `[StructureSize] 레지스탕스 본부(HQ_...) 스프라이트 a×b → Scale s (보이는 크기 …, 박스 …)` — 건물마다 1줄
- 서버가 못 읽은 경우: `[StructureSize] 스프라이트 크기를 읽지 못함(서버)` → 클라 `서버 측정 없음 → 클라 측정값 전송` → 서버 `[StructureSize] …` 순서
