상태: **모델·CSV·스크립트·UI 반영 / Maker Refresh·플레이 확인 전.**

## 1. 건물 이름 개명

"지상 일반 생성 건물"처럼 구분용으로 지어 둔 이름을 메이플스토리 지명·시설명으로 바꿨다. **이름은 테크트리 조건 문자열의 키이기도 하므로** 모델의 `StructureName` / `BuildCondition*` / `UnitCondition*` / `HQCondition` 95개 값과 CSV 3개(`Name`·`BuildCondition`·`Function`)를 한 번에 바꿨다(`ModelBuilder`로 수정, 스크립트 `rename_buildings.cjs`). 모델 파일명·모델 ID·스프라이트는 그대로다.

### 같이 바꾼 스크립트
- `PlayMap/BuildComponent/BuildZoneLogic.mlua`: 헤네시스 계열 판정이 "이름이 헤네시스로 시작"이었는데 **버섯의 성**은 지명이 빠지므로 예외로 추가. 영역 밖 건설 안내 문구를 새 이름으로.
- 그 외 스크립트는 이름을 데이터에서 읽으므로 수정 없음(`GetRequirementText`의 "○○ 필요" 토스트, 정보창 이름, 잠금 표시 전부 자동 반영).

### 바꾸지 않은 것
- `Docs/CampWar-TechTree.md` 본문과 `메커톤/메이플RTS_건물스펙_v1.xlsx`는 옛 이름 그대로다. 이 문서의 표를 대응표로 쓰면 된다.
- 유닛 CSV의 `Line` 열(헤네시스/페리온/진화 등)과 `StructureBuffAura.TargetLine`은 건물 이름이 아니라 유닛 계열이라 그대로다.
- 이름이 마음에 안 들면 `rename_buildings.cjs`의 MAP 표만 고쳐 다시 돌리면 된다(현재 이름 → 새 이름으로 키를 바꿔서).

## 2. 영웅 스킬 쿨타임 표시 (커맨드카드)

- **UI**: `ui/UIGroup.ui`의 `UnitActionUI/Slot1~10`에 `Cool`(검은 반투명, Filled·Radial360, 위에서 반시계로 줄어듦) + `Cool/Sec`(남은 초, 노랑 외곽선) 추가. 기본 Enable=false.
- **서버 → 클라 동기화**: `Hero/Unit/HeroUnitSkill.mlua`에 `@Sync SkillCooldowns`("Q:남은초:전체초|W:...") 추가. 서버는 0.2초마다 `HeroSkillComponent._T.cooldownEndAt`에서 Q~T의 준비 시각을 읽고 **바뀐 키가 있을 때만** 보낸다(연계 영웅 소울마스터·스트라이커는 공유 쿨다운 키도 반영). 클라이언트는 받은 시점부터 자체 카운트다운하므로 매 틱 전송이 없다.
- **표시**: `UI_Scripts/UnitActionSpriteChange.mlua`가 0.1초마다 영웅 스킬 칸의 `Cool`을 켜고 `FillAmount = 남은/전체`, 10초 이상은 정수·그 아래는 소수 1자리로 초를 표시한다. 쿨이 0이면 덮개가 꺼진다.
- 영웅이 아닌 유닛의 고유 능력(돌진·도발 등)은 쿨다운 상태값이 없어서 이번엔 대상이 아니다. `SpecialAbilityComponent`에 쿨다운이 생기면 같은 `Cool` 덮개를 재사용하면 된다.

## 4. 팀원이 확인할 것
1. Maker Refresh 후 빌드 에러 0 확인(새 `@Sync` 프로퍼티 때문에 `.codeblock` 재생성됨).
2. 플레이: 일꾼 선택 → 건설 목록·잠금 토스트에 새 이름이 나오는지, 정보창 건물 이름이 바뀌었는지.
3. 테크 조건이 그대로 동작하는지(예: 헤네시스 무기점을 지으면 파란버섯 잠금 해제, 버섯의 성이 헤네시스 영역 안에서만 지어지는지).
4. 영웅 선택 → Q~T 사용 → 슬롯에 어두운 라디얼 덮개와 남은 초가 뜨고 0이 되면 사라지는지. 소울마스터 W/E/R, 스트라이커 E/R의 공유 쿨도 같은 칸에 뜨는지.
