## 1. 왜 바꾸나

지금 해금 조건은 "같은 계열 바로 앞 건물 하나"뿐이라 계열끼리 서로 엮이지 않는다.
스타크래프트 테란처럼 **건물과 유닛이 서로 맞물리는 테크트리**로 바꾼다.

> 예) 아카데미를 지어야 메딕이 열린다 → 이 게임에선 "헤네시스 업그레이드 건물을 지어야 파란버섯(힐러)이 열린다"

### 설계 원칙
1. **생산 건물 사슬**: 병영 → 팩토리 → 스타포트처럼, 다음 생산 건물은 앞 생산 건물이 있어야 짓는다.
2. **기본 유닛은 바로**: 생산 건물마다 기본 유닛 1~3종은 조건 없이 뽑힌다.
3. **특수 유닛은 테크 건물**: 힐러·탱커·특수 유닛은 업그레이드/조건 건물(=아카데미 역할)이 있어야 열린다.
4. **상위 유닛은 교차 조건**: 최종 유닛은 다른 계열 건물까지 함께 요구한다.
5. **새 건물 모델은 만들지 않는다**: 이미 있는 건물 모델만 사용. 조건 문자열만 바꾼다.

### 조건이 안 됐을 때 표시 방식 — **확정: 회색 잠금 표시** (✅ 반영됨)
- 전: 조건이 안 맞으면 목록에서 **아예 숨김**
- 후: 버튼은 **검은 덮개 + 필요한 건물 이름(노랑)**으로 보여 주고, 누르면 토스트로 **"헤네시스 업그레이드 건물 필요"** 처럼 알려 준다.
- 이유: 플레이어가 "무엇을 지으면 무엇이 열리는지" 볼 수 있어야 테크트리가 느껴진다.

## 2. 해금 조건 동작 방식 (현재 코드, 그대로 사용)

- 판정: `RootDesk/MyDesk/PlayMap/StructureComponent/BuildRequirementLogic.mlua` `HasAliveStructure(map, playerId, 조건)`
  - 내 소유 + 완공(`IsUnderConstruction == false`) + 파괴되지 않은 건물 중 `Structure_Info.StructureName`이 같은 게 있으면 통과
- 조건 문자열 문법
  - 빈 칸 = 조건 없음
  - `A,B` = **AND** (둘 다 필요)
  - `A|B` = **OR** (하나만 있으면 됨)
  - `|`와 `,`를 한 문자열에 섞는 건 지원 안 함
- 조건을 적는 곳

  | 무엇 | 컴포넌트 | 프로퍼티 |
  |---|---|---|
  | 일꾼이 짓는 건물 | `WorkerAction` (일꾼 모델) | `BuildCondition1~17` |
  | 영역 건물이 짓는 건물 | `RegionBuildAction` (영역 모델) | `BuildCondition1~4` |
  | 생산 건물이 뽑는 유닛 | `StructureAction` (생산 건물 모델) | `UnitCondition1~8` |

- 조건 값은 건물 이름(`StructureName`)과 **글자 하나까지 같아야** 한다. 띄어쓰기 주의.

## 3. 새 테크트리

`*` = 개편 전 값에서 바뀐 곳

### 3-1. 모험가

`영역 전개`(`Adv_ExtendTree.model`, 인구 +8) 모델이 있지만 그동안 아무도 지을 수 없었다. **서플라이 디팟 역할로 살렸다.**

```
세계수
 └ 영역 전개(인구+8) *
    └ 헤네시스 영역 *
       └ 헤네시스 생성 ─┬ 헤네시스 업그레이드 ─┐
                        │                      ├ 헤네시스 조건 건물 (업그레이드 + 페리온 생성)
                        ├ 페리온 영역 * ─ 페리온 생성 ─ 페리온 업그레이드
                        └ 엘리니아 영역 * ─ 엘리니아 생성 ─ 엘리니아 업그레이드
                                                          └ 엘리니아 조건 건물 (엘리니아 업그레이드 + 헤네시스 업그레이드)
 커닝시티 영역 (페리온 생성 또는 엘리니아 생성) ─ 커닝시티 생성 ─ 커닝시티 업그레이드 (+ 엘리니아 생성)
```

| 건물 | 선행 조건 |
|---|---|
| 영역 전개 (인구+8) | 세계수 `*스포아 건설 목록 슬롯5에 추가` |
| 헤네시스 영역 | 영역 전개 `*` |
| 헤네시스 생성 | 헤네시스 영역 |

| 페리온 영역 | 헤네시스 생성 `*` |
| 페리온 생성 | 페리온 영역 |
| 페리온 업그레이드 | 페리온 생성 |
| 엘리니아 영역 | 헤네시스 생성 `*` |
| 엘리니아 생성 | 엘리니아 영역 |
| 엘리니아 업그레이드 | 엘리니아 생성 |
| 엘리니아 조건 건물 | 엘리니아 업그레이드 + 헤네시스 업그레이드 `*` |
| 커닝시티 영역 | 페리온 생성 또는 엘리니아 생성 `*` |
| 커닝시티 생성 | 커닝시티 영역 |
| 커닝시티 업그레이드 | 커닝시티 생성 + 엘리니아 생성 `*` |

| 생산 건물 | 유닛 | 조건 |
|---|---|---|
| 헤네시스 생성 | 주황버섯 / 초록버섯 / 뿔버섯 | 없음 |

### 3-2. 시그너스

```
신수
 └ 지상 일반 생성(병영) ─┬ 지상 일반 업그레이드
                        └ 조건 건물 1(아카데미) *
                           └ 지상 정예 생성(팩토리) ─┬ 지상 정예 업그레이드 ─┐
                                                     └ 공중 유닛 생성(스타포트) * ─ 공중 업그레이드 ─┤
                                                                                                      └ 조건 건물 2 *
```

| 건물 | 선행 조건 |
|---|---|
| 지상 일반 생성 | 신수(에레브 본진) |
| 지상 일반 업그레이드 | 지상 일반 생성 |
| 조건 건물 1 | 지상 일반 생성 `*` (전: 지상 일반 업그레이드) |
| 지상 정예 생성 | 조건 건물 1 |
| 지상 정예 업그레이드 | 지상 정예 생성 |
| 공중 유닛 생성 | 지상 정예 생성 `*` (전: 조건 건물 1) |
| 공중 업그레이드 | 공중 유닛 생성 |
| 조건 건물 2 | 지상 정예 업그레이드 + 공중 업그레이드 `*` |

> 전에는 공중 업그레이드를 지어도 아무것도 안 열렸다. 조건 건물 2의 조건에 넣어 쓸모를 만들었다.

| | 정식기사 D / B (대공 원거리) | 지상 일반 업그레이드 `*` |

| | 상급기사 E / C | 지상 정예 업그레이드 |
| | 상급기사 D / B | 지상 정예 업그레이드 + 지상 일반 업그레이드 `*` |
| | 상급기사 A | 조건 건물 2 |
| 공중 유닛 생성 | 소울 / 플레임 | 없음 |

### 4-3. 회색 잠금 표시 (스크립트 수정) — ✅ 반영됨

| 파일 | 한 일 |
|---|---|
| `StructureComponent/BuildRequirementLogic.mlua` | `GetRequirementText(조건)`: `A,B` → `"A, B"`, `A\|B` → `"A 또는 B"` (토스트는 뒤에 " 필요"를 붙임). `FindBuildCondition(map, playerId, worker, modelId)`: 서버 재검증용 조건 찾기(일꾼 슬롯 → 내 영역 건물 슬롯 순, 없으면 nil) |
| `Unit_Action/StructureAction.mlua` `ChangeActionUI()` | 조건이 안 맞는 슬롯을 건너뛰지 않고 `Locked = true`, `LockReason = GetRequirementText(...)`로 목록에 포함. `GetConditionForModel(modelId)` 추가 |
| `Unit_Action/WorkerAction.mlua` `GetBuildList()` | 위와 같음 (`HQCondition` 체크는 그대로). `GetConditionForModel` 추가 |
| `Unit_Action/RegionBuildAction.mlua` `GetBuildList()` | 위와 같음. `GetConditionForModel` 추가 |
| `Mouse_Keyboard_Command/CommandCardLogic.mlua` | 받은 `Locked`/`LockReason`을 그대로 액션에 넘김. 잠긴 칸을 누르면 `LockReason`이 있으면 `"○○ 필요"`, 없으면 기존 `"준비 중"` 토스트. `RefreshCard()`(모드·위치 지정 대기 유지, 건설 목록이 열려 있으면 `SubSource`로 같은 목록 재오픈). `StructureNameOf()`(건설 목록 칸에 건물 이름 — 내 진영 CSV의 Name을 클라이언트에서 한 번 읽음) |
| `UI_Scripts/UnitActionSpriteChange.mlua` | `Slot*/Lock/Reason` 글자 = `LockReason` 또는 "준비 중" |
| `Player_Scripts/SpawnUnit.mlua` | `RequestSpawnUnit`·`RequestBuildStructure`에서 선행 조건 재검증 → 실패 시 `"○○ 필요"` 토스트 + `log_warning` |
| `StructureComponent/Structure_Info.mlua` | `OnSyncProperty(IsUnderConstruction / IsDestroyed)` → 내 건물이면 `_CommandCardLogic:RefreshCard()` |
| `UI_Scripts/BuildListUI` (옛 목록 UI) | 더 이상 열리지 않는 경로(BuildListShowEvent는 자기 자신만 보냄)라 손대지 않음 |

같이 처리한 것:
1. **서버 재검증** ✅: 조건 검사가 클라이언트 목록 생성 때만 있었는데, 잠긴 버튼이 화면에 보이게 되니 서버(`SpawnUnit`)에서도 `HasAliveStructure`로 한 번 더 막는다. 목록에 없는 모델(Arda 채집 건물 등)은 조건을 모르므로 통과.
2. **카드 새로고침** ✅: 건물을 선택해 둔 채로 선행 건물이 완공되면 잠금이 바로 풀린다. 파괴되면 다시 잠긴다.
3. **잠금 구분** (글자만): "준비 중(로직 없음)"과 "선행 건물 필요"가 같은 검은 덮개를 쓰고 `Lock/Reason` 글자만 다르다. 아이콘을 나누려면 `Slot*/Lock`에 스프라이트 하나 더.

## 5. 테스트 체크리스트 (map02)

- [ ] 시작 직후: 기본 유닛만 활성, 나머지는 검은 덮개 + 필요한 건물 이름
- [ ] 잠긴 버튼 클릭/단축키 → "○○ 필요" 토스트, 생산·건설 안 됨 (서버 로그에 `[SpawnUnit] 생산 거부`가 뜨면 클라이언트 잠금이 안 먹은 것)
- [ ] 선행 건물 **건설 중**에는 여전히 잠김, **완공 순간** 풀림 (카드를 열어 둔 채로)
- [ ] 선행 건물 파괴 → 다시 잠김
- [ ] AND 조건(예: 파이어 보어): 하나만 있으면 잠김, 둘 다 있으면 풀림
- [ ] OR 조건(커닝시티 영역): 페리온 생성 / 엘리니아 생성 중 하나만 있어도 풀림
- [ ] 모험가: 스포아 건설 목록에 `영역 전개`가 보이고, 고스트 크기가 맞고, 지으면 인구 +8. 헤네시스 영역은 영역 전개 완공 전까지 잠금
- [ ] 건설 목록 칸에 건물 이름이 뜨는지
- [ ] 진영별로 최종 유닛(버섯 샹들리에·서전아이·셰이드 / 상급기사A·이프리트 / 게오르크)까지 실제로 테크를 타서 뽑히는지
- [ ] 상대 진영 건물이 내 조건을 채우지 않는지 (PlayerID 구분)
